# 坐标系 / 单位 / 容差规范（coords.md）

> **这份文件解决一件事**：让判定代码、场地数据、三维模型三边对着同一套数和同一个原点。它是唯一真相源，**冲突时以本文件为准**。
> 来源：`科目二扣分规则表-对内版.md` 第 1 节 + 第 4.3 节。改这里之前先改规则表，再同步本文件。

> 三维模型与它的私有坐标系登记在 `assets.manifest.json`（见第 7 节），断言测试在 `src/modelContract.test.ts`。

## 1. 坐标系与单位

| 项 | 规定 |
|---|---|
| 世界坐标 | 右手系，X 向右，Y 向上（自上而下俯视），单位 **米**，double 精度 |
| 角度 | 内部一律 **弧度**，从 +X 轴逆时针；只在 UI 层转成度 |
| 时间 | **秒**（double）；仿真定步长 `dt = 1/60`；判定使用原始时间戳，不重采样 |
| 车辆参考点 | **后轴中心**。所有位姿 $(x, y, \theta)$ 指后轴中心，$\theta$ 为车头方向 |
| 车辆局部坐标 | +X 指向车头，+Y 指向车身**左侧**，原点在后轴中心 |
| 3D 映射 | 世界 $(x, y)$ → Three.js $(x, 0, -y)$。因为取了负号，**世界 +Y（车身左侧）在 3D 里对应 −Z**，与已有模型一致。几何计算全部在 2D 完成，3D 只负责显示 |

> **纪律：代码里不允许出现 `cm`、`度`、`km/h` 三个单位。** 转换只发生在输入解析和 UI 显示两处。

## 2. 参考车几何（大众新桑塔纳）

| 参数 | 符号 | 取值 |
|---|---|---|
| 车长 | `L_v` | 4.473 m |
| 车宽（不含后视镜） | `W_v` | 1.706 m |
| 车高 | `H_v` | 1.469 m |
| 轴距 | `l` | 2.603 m |
| 前悬 | `a_f` | 0.870 m |
| 后悬 | `a_r` | 1.000 m |
| 轮距 | `w_t` | 1.420 m（估计值：官方未公布，实车约 1.46—1.50。现有模型按 1.420 建的，改这个数要同步改模型） |
| 轮胎（矩形近似） | | 0.600 m × 0.190 m |

校验：`l + a_f + a_r = 2.603 + 0.870 + 1.000 = 4.473 = L_v` ✓

**车身四角（局部坐标，后轴中心为原点、+X 车头、+Y 车身左）**

```
(-a_r,  -W/2) = (-1.000, -0.853)
( l+a_f, -W/2) = ( 3.473, -0.853)
( l+a_f, +W/2) = ( 3.473, +0.853)
(-a_r,  +W/2) = (-1.000, +0.853)
```

世界坐标：$P_{world} = R(\theta)\cdot P_{local} + (x, y)$

**车轮**：中心位于前后轴 ± `w_t/2`，前轮再绕自身中心旋转阿克曼角

```
R  = l / tan δ
δ_i = atan( l / (R - w_t/2) )    // 内侧轮
δ_o = atan( l / (R + w_t/2) )    // 外侧轮
```

## 3. 容差与去抖

| 项 | 规定 | 理由 |
|---|---|---|
| 建模容差 `tol` | **0.02 m** | 判定界取标线**外沿**，越过外沿 2cm 才判违规。真人考官目视判断本就带 1—2cm 误差，容差是为了与人判尺度对齐，不是追求数学零误差 |
| 罚则死区 `deadzone` | **0.03 m** | 30cm / 50cm / ±5cm 这类阶梯阈值，两侧各留 3cm，进入后按不利侧取档，避免数值抖动来回跳档 |
| 扫掠子步 | **4** | 相邻帧之间插 4 个子步并求凸包，解决低采样率下"穿过去没判到" |
| 时间区间合并 | gap ≤ **50 ms** | 同一规则内的接触区间按此合并，避免一次压线被拆成几十段 |
| 时间上报精度 | **0.01 s** | 报告里 `tStart` / `tEnd` 的位数 |

## 4. 三条不变量（写代码时不许破）

- **I1 可复现**：同一轨迹两次判定，结果逐字段一致。判定层无随机数、无墙钟、无渲染依赖。
- **I2 可核对**：每条违规必须同时给出 `ruleId` + `t` + `penetration` + `part`（哪个轮/车身）+ `lineId`（哪条线），缺一即视为实现不合规。
- **I3 判定独立**：判定层不 import 任何 Three.js / DOM 代码，CI 用 node 环境跑。

## 5. 场地数据约定（`tracks/*.json`）

### 5.1 坐标系：**一套共享的考场坐标**，不是每个项目一套

所有项目的 `track.json` 用**同一个坐标系**，且**必须与 `models/场地白模.obj` 完全一致**——因为渲染是把模型和判定叠在一起看的，差一个偏移就是"画面上压了、判定说没压"。

> 技术方案 4.2 原来写的是"每个项目单独一张局部坐标系，加载时统一变换"。**那条作废**：现有模型里倒车入库和侧方停车已经在同一套坐标里（见下表），再套一层变换只会多一处出错的地方。将来接第二个考场时，才在最外层加一个考场变换。

**现有模型的实测坐标（2026-11-16 从 OBJ 直接算出，照抄即可）**

| 项目 | 范围 |
|---|---|
| 倒车入库 库位 | X `0.00 — 5.17`，Z `-1.17 — 1.17` |
| 倒车入库 车道 | X `-6.71 — 0.00`，Z `-4.51 — 4.51` |
| 侧方停车 车位 | X `0.00 — 7.71`，Z `-8.53 — -5.99` |
| 侧方停车 控制线 | X `0.00 — 19.60`，Z `-11.88 — -11.86` |
| 地面 | 40 × 40 m（X/Z 各 `-20 — 20`） |

### 5.2 字段

| 结构 | 字段 |
|---|---|
| `TrackConfig` | `id`、`project`、`vehicle`、`regions[]`、`lines[]`、`arcs[]`、`poles[]`、`spawn`、`timeLimit?`、`rules` |
| `FieldLine` | `id`、`kind`（`solid`/`dashed`/`stopline`/`pole`）、`a`、`b`、`width`、`insideNormal`、`judge`（`body`/`wheel`/`none`） |
| `Region` | `id`、`polygon`（CCW）、`tags` |
| `Arc` | `id`、`center`、`radius`、`a0`、`a1`、`width`、`side` |
| `Pole` | `id`、`p`、`radius` |
| `Pose` | `x`、`y`、`theta`（后轴中心，弧度） |

`spawn` 是**车辆初始位姿**，不是坐标系变换。

### 5.3 标线

- **按"中心线 ± 半宽"建模为带状多边形**：场内标线半宽 0.075 m（总宽 0.15），坡道停车线半宽 0.15 m（总宽 0.30）。
- 判定界取线的**外沿**，不是中心线。
- 曲线边缘用**圆弧参数**（圆心 + 半径 + 起止角），**不要离散成折线**：R=7.5 m 时 128 段折线的弦高仍有 0.9cm，与 2cm 容差同量级。
- 每条线必须带 `insideNormal`（指向合法一侧的单位法向）与 `judge`。

> ⚠️ 模型里的标线只有 0.030 m 宽，**不能拿来当 `width` 的依据**——JSON 一律写 0.15（坡道停车线 0.30）。

## 6. 三维建模对照检查（`models/` 里的 OBJ 必查）

建模已经先于本文件发生，所以要回头对一遍。**任何一项不对，现在改成本最低**——等 `track.json` 和判定挂上去再改，所有场地坐标都要跟着平移旋转重做。

| # | 查什么 | 正确 | 错的典型 |
|---|---|---|---|
| 1 | **单位是米** | 量车长 ≈ **4.473** | 量出 4473，说明用了毫米 |
| 2 | **朝向** | 车头朝 **+X**，车身左侧朝 **−Z** | 车头朝 −X，或左右反了 |
| 3 | **地面在 Y=0** | 轮胎触地点 Y = 0 | 车身中心在原点，半截陷在地下 |
| 4 | **导出前 apply transform** | scale = 1、rotation = 0 | Blender 里缩放过没应用，OBJ 带了一身 scale |
| 5 | **原点位置** | 最好在后轴中心（`x ∈ [-1.000, 3.473]`） | 在几何中心（`x ∈ [-2.24, 2.24]`）——**不用改模型**，登记到 manifest 让加载层吸收 |

> 坐标轴约定：**Y 向上、X 为车长方向、Z 为车宽方向**（与 Three.js / glTF 一致）。Blender 里若按 Z-up 建模，导出时选 Y-up。

> **建模的人不需要为原点返工。** 资产可以有自己的一套局部坐标系，但必须登记到 `assets.manifest.json`，由加载层统一吸收——见第 7 节。

## 7. 资产私有坐标系与登记

**原则：资产可以有私有坐标系，但必须登记。** 要求每个建模的人把自己的模型对齐世界坐标，等于把契约成本摊给 5 个人，而且错了没人发现。让加载层吸收，成本只在一处，且可测试。

**登记表**：仓库根目录 `assets.manifest.json`。一个资产一条，记录它自己的坐标系长什么样、要做什么变换、期望尺寸是多少。

```jsonc
"models/最简桑塔纳白模.obj": {
  "origin": {
    "note": "原点在车身几何中心，不在后轴中心",
    "translateToRearAxle": [1.2365, 0, 0]   // 后轴位于 X = -1.2365
  },
  "expect": { "lengthX": 4.473, "wheelbase": 2.603, "leftIsNegativeZ": true }
}
```

**加载层一句话吸收**（Three.js，只在加载时执行一次）：

```ts
const entry = manifest.assets[path];
geometry.translate(...(entry.origin?.translateToRearAxle ?? [0, 0, 0]));
```

之后 mesh 直接按后轴位姿放置，**不要每帧算偏移**。

**断言测试**：`src/modelContract.test.ts` —— 纯文本解析 OBJ，不需要 Three.js，现在就能进 CI。校验车长、车宽、车高、轴距、轮距、地面高度、左右侧，以及"后轴 + translate 是否落在原点"。

> 它防的是：模型被重新导出后原点或尺寸悄悄变了，画面上车轮压线、判定却说没压。**改模型的人不一定想到通知别人，但 CI 会。**

**变更流程**：换模型 → 测试红 → 读失败信息 → 更新 manifest 的 `translate` 或 `expect` → 重新绿。选择改模型而不是改登记表也可以，只要两边一致。
